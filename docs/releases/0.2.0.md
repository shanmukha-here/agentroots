# 0.2.0 release validation

Local release checks performed on 2026-09-22, Windows, Python 3.12.13.
This is correctness and packaging evidence, not a productivity benchmark.

## Verified

- 181 tests passed; one POSIX-permissions test skipped on Windows.
- Ruff passed for source, tests, examples, and benchmarks. Strict mypy passed.
- Frontend production build passed without changing the packaged graph assets.
- Codex and OpenCode JavaScript entry points passed Node syntax checks.
- Wheel and source distribution built successfully and passed Twine metadata checks.
- An empty environment installed the wheel and 55 base packages, including MCP SDK 1.30.0.
  The source test environment used SDK 1.29.0. The declared SDK floor matches that tested range.
- Installed CLI setup, candidate review, self-acceptance rejection, local-file hashing, and
  compact hook recall passed. Setup did not change actual client configuration or read private
  conversations during this check.
- A real MCP ClientSession over stdio discovered 16 tools and AgentRoots version 0.2.0.
  Compact and full context retrieval, short record expansion, project selection, and database
  override precedence passed. MCP reads left database and project registry bytes unchanged.
- A separate installed daemon served authenticated loopback health requests with the expected
  version. Upgrade tests reject mismatched/unknown daemon versions without starting a second one.
- The synthetic full workflow passed read-only history import, extraction, independent review,
  MLflow REST fixture fetching, failed-experiment recall, and Git-induced staleness. The stale
  finding was excluded from context; source fixture bytes remained unchanged.
- Package inspection found no generated databases, model weights, environments, work directories,
  source conversations, or dependency trees. Shipped Python and graph assets matched source bytes.

The development test environment emits an upstream pydantic-settings forward-reference warning.
It does not fail these checks. The isolated MCP smoke with newly resolved dependencies passed.

## Reproduce

From a checkout in a disposable Python environment:

```bash
python -m pip install -e ".[dev]"
python -m pytest -q
python -m ruff check src tests benchmarks examples
python -m mypy src --strict
npm ci --prefix frontend --ignore-scripts
npm run build --prefix frontend
python -m build
```

Install the resulting wheel in a second empty environment. Then, using the checkout's Python:

```bash
python -m examples.installed_flow_demo --python /absolute/path/to/clean-env/bin/python --output /path/to/demo
python -m examples.full_flow_demo --output /path/to/full-flow
```

On Windows, the clean environment's interpreter is `Scripts/python.exe`. These demos generate
synthetic state under the supplied output directory. They do not require or alter real conversations.

## Verification boundary

The live Codex agent/hook acceptance evidence documented in [hook evaluation](../hook-evaluation.md)
predates this release check. This run rechecked installed hooks, daemon behavior, MCP transport, and
synthetic workflows, not a new provider-backed interactive Codex/OpenCode session. OpenCode remains
experimental; Qwen and GLiNER model-quality experiments were not retrained or rerun for this release.

Linux and Python 3.11/3.13 are covered by the repository's CI configuration, not the local Windows
test result. Refer to the actual Actions run for their outcome. No polished demo video, model
weights, private benchmark inputs, or generated test outputs are published with this release.
